# patent-pack-pipeline

一套**专利交付包全流程 skill**：把工程素材（规格书、BOM、参数表、仿真报告、概念手册、渲染图）转化为可直接交付代理机构的一整套专利文书，并可选并行产出论文与项目申报材料。

它不是模板集合，而是一条**带质量门禁的流水线**——每个阶段通过检查才进入下一阶段，全程禁止编造。

---

## 1. 什么时候用它

**触发场景**（使用者提出下列诉求，或 AI 判断属于下列范畴时启用）：

- 为产品申请专利，制作**技术交底书**或**专利交付包**
- 做**专利挖掘与布局**（发明 / 实用新型 / 外观设计）
- 做**现有技术排查**、**FTO**（自由实施，即"卖这个会不会踩别人专利"）风险评估
- 需要**设计补全**（方案里缺某个机构的具体设计）、**EVT 分析级验证**、**法规适用性评审**
- **专利 + 论文**双产出，或需要"填名即报"的**项目申报材料**

**适用对象**：消费 / 工业硬件产品（外骨骼、背带、机电产品、训练机器人等）、科技项目申报。

**不适用**：

- 纯软件方法专利的代理撰写
- 出具正式法律意见（如侵权判定书）
- 向 CNIPA 的实际提交动作
- 需要样机的物理实测（本 skill 只做分析级验证，见 §4 纪律）

## 2. 使用方式：把 skill 丢给 AI

**不需要安装，也不需要你提前整理资料。把 skill 交给 AI，说一句你要什么；需要哪些素材，AI 会在流程中按阶段向你要，你在对话里上传即可。**

### 第 1 步：把 skill 交给 AI

- 在 GitHub 页面下载 ZIP，把 **zip 直接拖进对话**；
- 或 `git clone git@github.com:qq547820639/patent-pack-pipeline.git` 后，把整个文件夹拖进对话。

包里 `SKILL.md`、`references/`、`scripts/` 结构完整即可——AI 靠它们查规程、跑脚本。

### 第 2 步：跟着对话走

先用一句话说清需求：

```
用 patent-pack-pipeline 为这款腰部助力外骨骼做专利交付包：
发明 + 实用新型 + 外观设计都要，参数以 RC 冻结版为准，产品下月参展。
```

然后跟着 AI 的引导走：

1. **先收敛边界**：AI 只问最少必要的问题（技术主题一句话、专利类型、联系人占位策略），信息不全就跳过并注明假设，不反复打断。**未显式指定专利类型时，一律默认发明**（"方法 / 系统"描述的是权利要求形态，不是专利类型）。
2. **再按阶段要素材**：它会告诉你需要什么——规格书、参数表、BOM、结构图、仿真报告、渲染图等，PDF / Word / PPT / Excel / 图片都收。手头有什么传什么，暂时没有的直接说没有：它不会替你编，能合理推定的走设计补全（注明依据与假设），推不动的记进"待确认问题单"。
3. **缺运行环境它会提示**：产出 Word、扫描附图、打包这三个环节需要本机有 Python 3 和 pandoc。让它跑一次 `python3 tests/test_scripts.py`，开头会打印环境自检表，逐项列出 pandoc / numpy / Pillow / python-docx / matplotlib 是否就绪，缺哪个、影响哪个环节；缺什么 AI 会让你装，不会替你静默安装。

## 3. 流水线总览

阶段不可合并，各阶段有独立质量门禁：

| 阶段 | 内容 | 阶段 | 内容 |
|---|---|---|---|
| S0 | 素材评估与渲染（图片型 PDF 逐页渲染识读） | S7 | 二轮审查 + 修订（申请文件轮） |
| S0.5 | 案件边界收敛 | S8 | 打包交付 |
| S1 | 技术特征提取（逐条编号、参数逐字带公差） | S9 | 设计补全（缺失机构） |
| S2 | 现有技术排查（含 FTO） | S10 | 集成回写 |
| S2.5 | 参数矛盾与缺失处置表 | S11 | EVT 分析级验证 + 设计更正 |
| S3 | 专利地图（默认最大化布局） | S12 | 法规适用性分析 + 冲突裁决 |
| S4 | 交底书撰写（每件 1 个并行写手） | S13 | 收口交付 |
| S5 | 独立审查 + 修订（交底书轮） | — | 配套论文轨道（并行） |
| S6 | 附图 + 申请文件 | | |

**项目方已确认的默认规则**：专利地图取最大化方案（不问件数）；缺失机构默认执行设计补全而非留占位；遇到问题先处置再往下；设计内容不加 AI 来源标注、不写"须代理人复核"类备注；每项关键设计决策须给出依据 + 约束条件；允许与冻结参数冲突，但必须显式登记。

## 4. 不可违反的纪律

1. **零虚构**——素材与已核验检索中不存在的数值、结构、文献、测试结果，一律不得写成事实。缺失机构走设计补全流程补齐，禁止用占位冒充已确认结构。
2. **引用纪律**——背景技术只引用检索报告中已核验的条目（专利号逐字核对）；"未检索到 ≠ 不存在"，统一写"本轮检索未检出……，正式申请前以全库查新为准"。
3. **防御性措辞**——禁用"首次 / 填补空白 / 国际领先 / 首创"；差异化写成"与 X（公开号）相比区别在于……（可核验事实）"。
4. **商标禁令**——发明名称、权利要求、正文不出现产品型号或商标，统一用通用名。
5. **时序铁律**——同产品包各件建议同日提交，且务必早于产品公开发售、展会公开、论文投稿。
6. **EVT 诚实边界**——分析、复算、仿真可执行；**物理实测严禁编造**。无样机时输出"测试规程 + 预测值 + 合格判据 + 待物理实测"，每份报告逐字写入投产总则："任何设计内容在对应物理实测全部通过前不得进入投产阶段；分析验证结论不构成投产依据。"

- **跨文件对账会互相抵消成绿，同一份文件内的那一格得单独核**：契约那条 `defined_rules` 是

  收尾行自报「同文件对账 N 个脚本/M 个号」，并配两份最小样本（打了没列的那份必须点名、
  补齐的那份必须闭嘴）——没有这一对，真语料上那个"全部为空"分不清合规与恒真。
  claims 那一族的号既不在 `Finding(` 里也不带 `→ `，所以它**不进这一格**（硬凑只会撑大分母、
  让断言永真），那一族仍由跨文件那条管——写清楚哪些面没覆盖，比把格子画大更要紧。
- **覆盖账与开火面是两本账，谁也不许替谁**：收尾那行 `实判判据 N 条` 记的是**适用域读到了**的判据条数，
  与这条判据有没有开火无关——"看不见"走未判、"读到了没问题"走已判零违规，两者不许互相冒充。
  第 41 轮之前节面判据（Q7／Q8／Q12）的 `seen.add` 写在 `if 命中:` 里面，于是**合规的包只自报 9 条而不是 12 条**、
  "有节无项"的真工件自报 0 条，读者分不清"跑了没发现问题"与"根本没跑"（第 36 轮 Q7/Q8、第 39 轮 Q12 照抄同一形状）。
  规矩：判据的适用域一旦被扫到就记账；配套常驻档必须**同时**钉两侧——合规档"记满 N 条"、
  适用域少一格时"跟着让出那一格"（去掉标记对照表 ⇒ 11 而不是 12），以及反方向"没读到节 ⇒ 0 条＋实判 0 个包"。
  包级账（`实判 N 个包`）与条级账是两格，零开火的合规包也得算进包级账，别只修上面那半。
- **法源引文分两种用途，用错一份就等于造出一条没有的"没有"**：正向引句（"细则第 X 条写着 Y"）
  引 769 号《修改决定》（留底 `.codebuddy/attest/gz769.htm`）没问题——被改动的条文它在正文里全文引用；
  但**否定主张（"细则没有这句／这一格不归细则管"）只能引合并现行全文**
  （`.codebuddy/attest/xzfg1697.htm`，国家行政法规库 LawID=1697，含到第一百二十二条），
  并且要配一条"同一份里别的词确实取得到"的对照（如 `技术领域` 3 次）来证明那个 0 不是抓取失败。
  决定那份未改动的条文整条都不在其中，从它里面读不到任何东西都证明不了什么。

- **取法也要写全，"去标签去空白"这一句不够**：同一份 `xzfg1697.htm`（原始 113,780 字）
  只 `re.sub('<[^>]+>')` 再去空白 ⇒ **29,380 字**且 `'300'` 命中 **1 次**（`<style>` 里的数字——去标签不剥样式正文）；
  先剥 `script`/`style`/`<!-- -->` 再走同样两步 ⇒ **25,967 字**、`'300'` **0 次**。
  而我们引作否定依据的正是"300 与 摘要文字部分 都 0 次"那句话 ⇒ **照文档字面重跑，负结论会被自己的留底当场反驳**。
  规矩：凡引"某词 N 次"的读数，出处必须把取法一步一步写死，并留一件两法并排的复算件
  （`.codebuddy/attest/r75_lawcount.py`，读数 `r75_lawcount.out`；`gz769.htm` 同法 37,274／39,761）。
  顺带一条方向性事实：加垃圾只会造出**假阳性**（把样式数字读成命中），不会造出假阴性 ⇒
   sloppy 取法下的 0 是安全的，被推翻的是那种取法下的非 0 读数。
- **字段型判据的循环不许停在第一处匹配**：`for …: if m: … break` 这个形状让"第二处藏一个违规"
  同时从**共用这一行的所有尺子**里消失，而终端上的读数与真判过完全同形——第 44 轮给 R15 复用 R7 那个循环时
  才发现它从建门起就 `break` 在第一处（发明名称写两处的文书今天没有，所以从没露过脸）。
  复用别人的循环加判据，先问这个循环走几遍；改成全遍时 `for/else` 的未核分支要一起换成显式旗标

## 8. 常见疑问

**Q：素材不全（只有概念描述）能跑吗？**
能。能合理推定的走设计补全（注明依据与假设），推不动的进"设计方确认问题单"，不会替你编。

**Q：专利类型怎么定？**
不指定即默认发明；结构改进可加实用新型；消费级产品强烈建议加外观设计。默认给出最大化布局，由使用者按预算取舍。

**Q：能同时出论文吗？**
能，但必须提前声明——论文是并行轨道，且严守**先申请专利、后发表**的时序（发表过早会破坏新颖性）。

**Q：检索结果能当 FTO 结论吗？**
不能。输出的是风险清单与规避建议，属情报层面；正式结论需专业机构出具。

**Q：为什么文档里不写"首创""国际领先"？**
无法证明，且会在后续审查或无效程序中成为把柄。统一改用可核验的对比写法。

**Q：脚本报错怎么办？**
先看 `references/tooling-pitfalls.md`；环境类问题跑 `python3 tests/test_scripts.py` 定位。
