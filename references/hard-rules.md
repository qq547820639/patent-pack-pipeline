## 1. 零虚构纪律
- 未实测/未在素材出现的数值不得出现；设计推导值标"设计计算值"；仿真值标"仿真值（P0 降阶仿真）"类产品口径；素材 DRAFT 状态数值带"设计目标（版本）"+TBD/TBC/ASSUMPTION 状态标注。
- 源文档没有的参数写"由实施例试验确定"或占位符【待设计方确认：xxx】，严禁编造。
- 验证结论（测试 Not Run 的项）不得写成已达成。

## 2. 引用纪律
- 背景技术只允许引用检索报告中已核验条目（专利号逐字一致，含授权日/优先权日核对）。
- 检索报告自身的"已核验"不得是自称：格式与字段见 templates §C，由 `scripts/verify_search_report.py` 判 V1–V6（V3 只在线核 DOI/arXiv，专利存在性无可用无密钥源；V5/V6 是 §2.1 那两条的句法形状部分，见本文件 §2.1）；md 与 docx 两通道同判据；检索报告外的公开号禁止出现；指名品牌/产品仅在检索报告记录范围内引用。此条由 `scripts/check_iron_rules.py` R5 实跑（取背景技术节公开号集合 − 检索报告公开号集合，差集非空即判红）；不给 `--search-report` 时报"未核"，既不折成违规也不折成合规。
- 查新声明统一句（背景技术末尾）："以上为背景技术的初步检索结果，正式申请前建议由专利代理机构进行专业查新检索。"——此为内容级范围声明，保留。
  此条由 `scripts/check_iron_rules.py` R9 实跑：**判在该节内**是否逐字出现（写在别的节不算兑现），
  比较前只剥空白（作者软换行不是改措辞），标点与汉字一个都不许差；没有背景技术节时报"R9 未判"，
  既不折成违规也不折成合规（`new_product_package.py` 的说明书骨架就没有这一节）。
  "置于本节末尾"这半条**只提示不判红**——位置判定会把表格/引文当节边界，误伤面本机量不出，故写在此处而不是伪装成已执行。
- arXiv 预印本标注"预印本"。此条由 `scripts/verify_search_report.py` V4 实跑（离线判：只看 arXiv 行的「类型」列
  有没有这三个字，不依赖网络）；表里没有「类型」列或报告里没有 arXiv 条目时报"V4 未判"，两种"看不见"都不折成违规。
  扩展方向（本轮未证实、没做）：Crossref 的 work 记录带 `type` 字段，理论上能把 bioRxiv/medRxiv 那类 DOI 也认成预印本；
  本机两次请求分别拿到 HTTP 400 与 404，没读到过一个真实字段名，所以不据此写判据
  （两条 endpoint 形状与出处见 `scripts/verify_search_report.py` docstring 第 17 行：
  `/works?filter=type:…&select=…` 与 `/types/posted-article/works`）。

### 2.1 查新方法纪律（吸收自 handsomestWei/patent-disclosure-skill，2026-09-04 评估）
- **两段式查新**：第一轮关键词召回（web_search/CrossRef/arXiv/可用插件）→ 从命中条目抽出 IPC/CPC 分类号（取 1–3 个高频前缀）→ 第二轮按分类号收口（同分类号+更贴本案手段的核心词）——显著高于单层关键词检索的相关度。
  这条里的"写了分类号就得是合法 IPC/CPC 形状"由 **V6** 实跑（独立「分类号：」行、或检索式里挂在 IPC/CPC 关键字后面的 token 都算，须合 `A42B3/20`／`E04G17/00` 式）；
  **没做第二轮不判红**——§2.1 是方法建议，判红等于替纪律新增"必须两段式"，所以无分类号时 V6 走未判。
- **检索词拆分纪律**：2–8 个有检索意义的语义块（专业术语/名词短语/名动组合），空格分隔；
  **这一条的句法部分由 `scripts/verify_search_report.py` V5 实跑**：一行里 "；" 分隔的多条式子各数各的块，
  `AND/OR/NOT` 与括号不计块（模板 §10 那行示范式按空格切是 10 段，去掉连接词与 (S1)/(S2) 标号才是 2–8 个语义块——
  第一版没做这一步，判据把自己的范本判红了）；一整串无空格中文当唯一检索词判红、单字块与
  "检索/增强/系统/方法"泛义词判红；没写「- 检索式：」或还是【待填写】占位 ⇒ V5 未判。
  **"块选得贴不贴本案手段"是语义判断，仍归 reviewer，V5 不冒充。禁止把无空格整句长中文当唯一检索词（易被当整句 AND 而零命中）；禁止拆成过碎单字或泛义词（"检索/增强/系统/方法"）。
- **保底规则**：第二轮筛后 <4 条 → 从第一轮按同一分类号+手段沾边回补至约 4–6 条；仍不够 → 仅用分类号再查一次或带相邻分类号；还不够 → 如实写"检索范围内近邻较少"，**禁止编造条目凑数**。
- **查新 vs 著录清单分离**：技术查新（一词一页、不翻完）与申请人/发明人清单式穷尽检索是两个用途，不混用、不互替。
- **写入背景技术的门槛**：分类号重合+技术手段对得上才进 1.1/2.1；禁止把召回全集整表写入。
- **CNIPA 通道现状（本环境实测 2026-09-04；2026-09-25 四项逐一复核仍一致；
  2026-09-27 第三次复跑，四项照旧——命令 `curl -sS -m 20 -o /dev/null -w 'code=%{http_code} time=%{time_total}s' https://<host>/`，
  读数 `epub 000/20.00s`、`pss-system 412/0.35s`、`www 200/0.43s`，留底 `.codebuddy/attest/r54_cnipa.log`，该目录不入 git）：epub.cnipa.gov.cn 与 patents.google.com 不可达（curl 超时）、pss-system 返回 HTTP 412、www.cnipa.gov.cn 返回 200 可达——CNIPA 著录检索须用网页版人工执行或在可达环境执行；该仓库（handsomestWei/patent-disclosure-skill）的 Playwright 工具在 CNIPA 可达环境可直接复用。可达性会随网络环境变化，动用前按当次实测为准，不得沿用本条结论。

## 3. 防御性措辞与划界
- 禁用词：首次/填补空白/国际领先/首创/国际先进（作新颖性或水平声明时）。其中 首创/填补空白/国际领先/国际先进 四类由 `scripts/check_iron_rules.py` R1 无条件判红；"首次"只在声明语境判红（"首次加载配置表"这类正常描述不判），语义层的新颖性声明判断仍归 reviewer。
- **摘要与简要说明两节内不得出现商业性宣传用语**，由 `scripts/check_iron_rules.py` R10 实跑。法源两句逐字读自
  国务院令第 769 号修订后《专利法实施细则》全文（留底 `.codebuddy/attest/gz769.htm`，抽取读数见
  `r58_law_quotes.log`，该目录不入 git）：第二十六条末句"摘要中不得使用商业性宣传用语"、
  第三十一条末句"简要说明不得使用商业性宣传用语，也不得说明产品的性能"。
  **适用域只在这两节**（摘要节认「说明书摘要」「摘要建议稿」，简要说明节认「简要说明」「外观简要说明」标题行；
  正文里"简要说明：…"的内联写法不算节，那是 C5 的触发词面），写在别的节不报——两句话各管一件文书，
  扩成全文禁词等于替纪律新增要求。**词表是房内口径**：细则只写"商业性宣传用语"六个字、没有列举；
  《专利审查指南》（2023，局令第 78 号）原文本机已逐字读到（2026-09-27 第 38 轮，留底
  `.codebuddy/attest/zhinan2023_ahippc.txt`，复算命令见 README §6），而**指南同样没有列举词表**——
  它只在第一部分第一章 §7.7（说明书）与 §7.8（权利要求书）各给了一句"不得使用商业性宣传用语
  以及贬低…他人或者他人产品的词句"，一个词都没列。
  所以每个词都是"我判它是宣传语"，不得冒充法条列举。被排除的词都撞技术语义
  （第一＝序数、绝对＝绝对式编码器、最优＝最优实施例、顶级＝顶级域名、高端＝高端交换机、
  完美＝完美匹配、终身＝终身学习、免费＝免费开源库、最佳＝最佳实施方式、首选裸形、领先裸形），
  排除表由 R10 的常驻"撞车词必绿"档钉住。**R10 的词表与 R1 的四个词交集必须为空**
  （那四个全文都报，节内再报一遍是同一件事占两个原告），这一条有常驻前提断言守着。
  第三十一条那半句"也不得说明产品的性能"**没有执行点**：什么算"说明性能"要读技术内容，
  写在本节而不是伪装成已执行。

## 4. 权要撰写规则
- **权要形状已由 `scripts/check_claims.py` 实跑成 Q1–Q13**（Q1–Q8 法源逐字对过 769 号令正文；
  Q9–Q11 与 Q13 逐字对过《专利审查指南》（2023，局令第 78 号）正文，见本节末与 README §6 的留底与复算命令）：
  Q1 权项编号是从 1 起的连续阿拉伯数字（第二十二条）；Q2 至少一个独权且每个独权排在所有从权之前
  （第二十三、二十四条；"应当只有一个独权"的**个数**那一半只出提示不判红——产品+方法并列独权是常见写法，
  算不算同一组要读技术方案）；Q3 从权只能引用在前的权项且引用号须真实存在（第二十五条）；
  Q4 多项从权不得以多项从权为引用基础（第二十五条）；Q5 权要里的附图标记必须写在括号内（第二十二条），
  且只认那张「标记｜名称」对照表里真实存在的号——正文里的自由数字（"拉脱力 90N"）不当标记，否则这把尺子只会造假红；
  Q6 从属权利要求条数落在档位内（发明 7–10、实用新型 4–8）。**档位是房内口径、不是法条**：细则没有任何条数区间（超过 10 项只是加收申请费，不是驳回理由）。
  类型由 `--type` 告知；没告知时退到两型并集 4–10——仍能抓"少到 3 条""多到 11 条"，但只有一型容得下时出「Q6 部分未判」提示而不是判红，因为机器不知道本案是哪一型（清单里那一列可能整张表都没行）。类别清单与"认不出就不猜"由本模块的 `PATENT_TYPES`/`type_of` 一处持有，打包侧的 P8 import 它（两处各抄一份迟早漂）；「专利清单」有没有真填、填得对不对，由 P8 在打包那一步核，Q6 不猜也不重复判。
  三态：包里没有「权利要求书」节 ⇒ Q1–Q13 全部未判（权要交给代理机构撰写时本就没有这一节），不折成合规。
  **Q7 权利要求书里不得有插图**、**Q8 不得用"如图…所示／如说明书……部分所述"指回别的文书**
  （同条一款的两句禁令："可以有化学式或者数学式，但是不得有插图。除绝对必要的外，不得使用……"）。
  Q7 的 md 通道认图片语法；docx 通道由 `docx_text` 把含 drawing/object/pict 的段落折算成一行
  `![](docx-embedded-object)`——判据作用在文本面上，两通道同一条正则；**表格里的图不在此列**
  （表格分支按格取文），登记为已知盲区。Q8 只判带编号的形状，无编号的"如图所示"误伤面没量过、不判；
  "除绝对必要的外"是法定例外，真踩到时由 reviewer 裁，不归机器。三态与整族相同：
  没有权利要求书节 ⇒ Q1–Q13 全部未判。

  句号位置这类形式细则，是指南把它们写成了可判的形状（三句逐字抄自本机留底的 613 页 PDF 抽取件，
  页码给"PDF 页／印刷页"两套）：
  **Q9 权项内不得出现"例如／最好是／尤其是／必要时"**（第二部分第二章 §3.2.2，PDF p165／印刷页 2-29：
  「权利要求中不得出现"例如""最好是""尤其是""必要时"等类似用语」，理由是这类用语会在一项权利要求中
  限定出不同的保护范围）。**只收指南逐字点出的四个词，不扩表**——同节的"厚／薄／强／弱"那支进来
  就把尺子变成假红制造机：中文没有词边界，"压缩强度"里的"强"会当场开火（该形状已钉进常驻反向档）。
  **Q10 权项内不得用"约＋数字"限定数值、不得出现"或类似物"**（§3.2.2，PDF p166／2-30：
  「在一般情况下，权利要求中不得使用"约""接近""等""或类似物"等类似的用语」）。

- 实用新型：1 独立+4~8 从属（从属条数由 Q6 实跑，`--type 实用新型`），**只写结构特征、不写方法步骤**；功能限定须落到结构关系（"A 与 B 并联连接，A 失效时载荷全部由 B 承担"式）。
- 独权限缩检查：对照最接近在先技术逐要素区别；上位概念（如"模块化""快拆""镂空"）已被公开的，独权必须含具体结构组合。
- **权要数值口径（实战反复踩坑项）**：设计目标值/推定值/未实测指标**一律撤出权要**，改功能性限定（"经安全评审的阈值以下""在预设横移速度限幅内""按预设上限截断""在来球到达预测落点之前"式），绝对数值留说明书实施例；冻结的工程参数（设计值而非性能验证值）可入从权。
- **实用新型客体越界自查（实战坑）**：时序/动作步骤不得入权；改写句式——"X 动作在 Y 时机完成"→"所述驱动件使能端与发射使能链连接，所述发射使能链设有在 Y 时机输出设定值的信号端口"；"动作时序同步"→"所述联动触点构造成响应于节拍信号而断开或导通"。
- **权要数值算术自洽自查（实战坑）**：权文内数值组合代入边界值复算一遍（如"球质量 0.26–0.28kg、来球 ≤25m/s、回球 ≤20m/s 时冲击脉冲不大于 11.6N·s"——0.28×(25+20)=12.6>11.6 即自相矛盾）；权文引用的推导值与其约束条件同权核验。
- **专利法 25 条客体风险（纯方法框架）**：教学/评估/推荐类框架的独权必须含"技术手段落地"锚点（如执行驱动模块将生成结果转换为设备物理参数并驱动执行+实测数据回流闭环），否则有被认定为智力活动规则的风险。
- 权文内不嵌"（待确认）"注释——占位说明移至说明书（`scripts/check_iron_rules.py` R3 判红；括号内含说明文字的写法如"（待确认：型号）"同样判红）。
